# Multiple local Anthropic accounts

Implement the account model described by ACCT and thread it through credential resolution, request attribution, meter state, gates, pings, setup and the TUI.

## Implementation

- [ ] Add append-only schema migrations and store types for accounts, credential digests and account-aware meter, allowance, ping and ledger state.
  - [x] Add learned accounts and credential-digest bindings, including deferred identity resolution and ledger backfill.
  - [ ] Add account-aware ledger, meter, allowance, ping and lane state.
    - [x] Key meter snapshots and allowances by account.
    - [x] Make the account part of a lane's cache identity, where the provider has one.
    - [x] Record the account a ping opened a window for, and read the window it checks on that account alone.
- [ ] Schedule one ping per account, each sent with that account's credential.
  Deferred: it needs credential selection, which this card does not build. Until then a provider with several accounts cannot tell which account a ping will land on, so it always sends and reads the account back off the rows the ping produced.
  - [x] Add account and credential-digest columns to the ledger model, including rows imported and generated by existing paths.
- [ ] Resolve Anthropic subscription credentials from local accounts and capture a non-secret digest for every credential sent upstream.
  - [x] Capture the credential only after provider-specific cleanup and injection, then attribute completed Anthropic attempts to its digest.
  - [x] Parse a bounded local multi-account credential file into digest and email facts without retaining token values.
- [x] Discover and resolve account identities without delaying requests, then retroactively attribute rows for a resolved digest.
  The local source re-reads itself when it cannot answer, so a refreshed token resolves to the same login without a restart. The operator names a digest no source resolved, from the accounts page. Asking the upstream is the chain's second step and is a MAY, so it is not built.
- [ ] Key cache identity, meter state, quota fitting, allowances and pings by account.
- [x] Migrate historical unattributed rows through setup and refuse other commands until setup completes.
- [x] Render the account-aware dashboard and the accounts page.
  The dashboard and the accounts page read the store directly, the way the dashboard already read it, so no service snapshot or control endpoint was needed. Naming an account writes through the store like the TUI's existing grant and revoke.
- [x] Add focused tests for migration, attribution, account isolation and account-aware rendering.
